Overview

What it is

Atlas is a persistent AI assistant built on top of OpenClaw, designed to operate autonomously across sessions rather than reset on each conversation. It maintains long-term memory through a vector store, manages its own cron schedule, monitors Discord channels in real-time, and orchestrates specialised sub-agents for complex tasks.

The design philosophy is push-based, not pull-based. Atlas is not a chatbot that waits for prompts. It runs background jobs, monitors for events, consolidates memory weekly, and surfaces relevant context proactively. When a task requires extended computation, it spawns sub-agents and receives their results asynchronously.

The goal was a system that behaves like a senior member of a one-person team: available, context-aware, and capable of making good decisions without constant oversight.

Architecture

Multi-model orchestration

Different tasks warrant different models. Atlas routes work to the appropriate model based on task type, cost constraints, and required depth. All models are accessed through GitHub Copilot subscription at no additional cost.

Capabilities

What Atlas can do

  • EXEC
    Autonomous task execution. Runs shell commands, manages files, executes Python scripts, and commits code to Git without waiting for confirmation on safe internal operations.
  • MEM
    Persistent memory. ChromaDB vector store indexes 100+ workspace files. Semantic search retrieves relevant context from past sessions, project notes, and design decisions. Per-channel Discord memory maintains thread context independently.
  • AGENT
    Sub-agent orchestration. Spawns specialised sub-agents for long-running tasks (e.g. building entire project pages, running code reviews). Results are push-based — sub-agents announce completion rather than being polled.
  • MONITOR
    System monitoring. Discord monitor bot watches channels for relevant events. GitWatch auto-commits workspace changes on a schedule. Five cron jobs handle morning briefings, market scans, study reminders, and weekly memory consolidation.
  • RESEARCH
    Web research. Perplexity API integration for real-time web search with citations. Used for market data, news sentiment, and technical research. Separate from the LLM context to avoid contamination.
  • CODE
    Code generation and review. Writes production-grade code with no AI fingerprints. Can spawn Codex or Claude Code in a PTY session for extended coding tasks that require iterative tool use.

Memory Architecture

How context persists

Three memory tiers, each with a different latency and precision tradeoff:

# Tier 1 — Hot context (session-scoped)
SOUL.md       # identity, persona, operating parameters
USER.md       # who Atlas is helping and their preferences
PROJECT_TRACKER.md  # active work, next actions, milestones

# Tier 2 — Rolling episodic (daily files)
memory/YYYY-MM-DD.md  # raw session logs, decisions, events
memory/current_context.md  # active continuity thread

# Tier 3 — Vector store (semantic search)
memory/atlas_core/  # ChromaDB index, 100+ files
query: atlas_search("solana backtest results")
result: top-k chunks ranked by cosine similarity

The consolidation cron runs weekly to distil daily logs into MEMORY.md — the curated long-term store. This keeps the hot context small while preserving significant historical signal.
