How I Built a Trading System
That Follows Smart Money on Solana

Benedict Anokye-Davies Feb 2026 ~12 min read Python · Solana · Helius API

99.37% of tokens launched on Pump.fun fail. They get created, attract a few hundred dollars of volume, and die — usually within 24 hours. The 0.63% that graduate to a real DEX are the only ones worth trading. The question is how you find them before the crowd does.

This is the story of building AxiomFlow QuantLab — a signal engine that watches 57 alpha wallets around the clock, detects when profitable traders coordinate buys on the same token, and scores those opportunities through a weighted multi-factor model before retail discovers them. The system has evaluated 8,000+ candidate signals. A backtest on the most tradeable subset showed +8.3% return-on-capital. And there’s one debugging story in here that took weeks to find, because the bug was so obvious it was invisible.

the_problem

The naive approach to meme coin trading is to watch DexScreener trending and buy whatever looks like it’s pumping. That’s how you become exit liquidity. By the time something appears on a trending list, someone else already found it earlier, bought lower, and is now selling into you.

The more honest question is: who consistently makes money in this environment, and how do you see what they’re doing in real time? Those wallets exist. On Solana, transaction history is public. If you can identify wallets with sustained win rates across dozens of trades — and then monitor their buys at low latency — you have a real information edge.

Core Thesis

Track alpha wallets (historically profitable traders) via the Helius Enhanced Transactions API. When 2+ alpha wallets buy the same token within a 5-minute window, treat that clustering as a high-priority candidate and score it before the crowd arrives.

architecture_overview

AxiomFlow V15 is intentionally simple at the top level: multiple data feeds emit token candidates, a unified scoring engine assigns a composite score, veto gates hard-reject obvious trash, and a conviction-based sizer decides whether the system would allocate $10, $15, or $25 on a $300 bankroll.

The feeds are not equal. In V14 I made the mistake of treating DexScreener as the primary source and “smart money” as a passive filter. The V15 overhaul flips that: smart money becomes the primary signal.

smart_money_flow_detection

The heart of the system is SmartMoneyFlowDetector. Every scan cycle it pulls recent transactions for the top alpha wallets using Helius’ Enhanced Transactions endpoint (/v0/addresses/<address>/transactions), extracts net token inflows, and records “recent buys” in a 5-minute sliding window. If a mint shows up across multiple wallets in that window, it emits an AlphaAlert.

Python src/intelligence/smart_money_flow.py 
def scan_alpha_activity(self) -> list[AlphaAlert]:
    # lookback_seconds defaults to 300 (5 minutes)
    cutoff = int(time.time()) - self._lookback_seconds

    for wallet in alpha_wallets:
        txs = get_address_transactions(wallet, limit=self._per_wallet_tx_limit, timeout=10)

        for tx in txs:
            tx_ts = _safe_int(tx.get("timestamp"))
            if tx_ts is None or tx_ts < cutoff:
                continue

            for mint, _ in self._extract_token_buys(wallet, tx):
                self._record_buy(AlphaBuy(wallet=wallet, token_address=mint, amount_usd=0.0, timestamp=tx_ts))

    # Emit an alert if 2+ wallets bought the same mint within the window.
    for mint, buys in self._recent_buys.items():
        wallets = sorted({b.wallet for b in buys if b.timestamp >= cutoff})
        if len(wallets) < 2:
            continue
        alerts.append(AlphaAlert(token_address=mint, alpha_count=len(wallets), urgency=_clamp(len(wallets) / 5.0), wallets=wallets))

Two implementation details matter more than most people expect:

  1. Helius Enhanced TXs returns parsed tokenTransfers already decoded. If you’ve ever tried to extract SPL token balance deltas from raw Solana instructions at scale, you’ll appreciate how much work this avoids.
  2. “2 wallets within 5 minutes” is not arbitrary. One wallet buying is noise. Two wallets in a tight window is intent. Three+ wallets is high conviction.
Helius gotcha

The enhanced endpoint is api.helius.xyz. The legacy api.helius.dev domain is dead. If your scan loop returns empty arrays without errors, verify the base URL first.

multi_factor_scoring

Smart money clustering is the source of candidates. Scoring is how we avoid buying every cluster. A meme coin can have alpha wallets involved and still be toxic: thin liquidity, mint authority active, deployer dumping, or a distribution too concentrated to survive.

V15 uses a linear weighted composite (MFA score). The weights are calibrated from real diagnostics: V14 failed because it had weak candidate sources, not because its safety filters were too strict. The fix was to make smart money dominant and demote lagging indicators.

The smart money sub-score is not just “how many alpha wallets touched it”. It’s a combination of alpha wallet count (scaled so 4 wallets is already max conviction), average alpha win rate (55% is elite in this domain), and an alert bonus if the token was discovered via coordinated wallet activity.

veto_filters

Before scoring, hard veto filters reject tokens immediately. These aren’t “low score”. They’re structural reasons the trade should never exist.

  • liquidity < $10,000 (thin pool, you’ll move the market)
  • token_age > 60 minutes (late entry; most edge is gone)
  • holders < 50 (too early; mostly dev + bots)
  • mint authority active (infinite supply risk)

In the V14 diagnostics, most rejections were distribution_block and rugcheck_danger. That wasn’t a bug. It was evidence that the filters were doing their job and the candidate source was garbage. V15’s fix is not “turn down the filters”. It’s “stop feeding them trash”.

conviction_based_position_sizing

V15 uses conviction tiers rather than a continuous sizing function. This is deliberate. With tiny bankrolls, execution quality dominates; you want discrete, predictable sizing. The implementation assigns a tier based on confluence, then maps tier → % bankroll and dollar amount.

Tier 1 (graduation + 2+ alpha + social): $25 (8.3%)
Tier 2 (alpha wallets, no graduation):   $15 (5.0%)
Tier 3 (graduation only or 1 alpha):     $10 (3.3%)

A Tier 1 signal means three independent channels agree: smart money flow, a graduation event, and social presence. Tier 2 is “alpha confirmed, but no graduation”. Tier 3 is “speculative — small size”. It’s a VC-style asymmetric structure: many small losses, rare large wins.

the_debugging_story

The system was dead for weeks.

Every scan cycle returned zero alpha hits. Metrics logs showed alpha_wallet_hits: 0. The Enhanced TX API was returning data. The parsing code was running. No exceptions. It looked like “no alpha wallets are trading”, which is obviously false.

Root cause

Every wallet address in the DB was stored lowercase. Solana addresses are base58 and case-sensitive. A canonical address and its lowercased version are different strings. The set intersection between “alpha wallets” and “observed wallets” was always empty.

The fix was not complicated. The painful part was that everything looked “fine” because the system wasn’t crashing. It was producing valid empty outputs.

The real lesson: never normalize Solana addresses. Store exactly what the chain returns. Put the constraint at the insertion point. Silent mismatch bugs are the worst kind.

results

8,000+ signals evaluated
57 alpha wallets tracked
+8.3% ROC (backtest)
30.8% win rate (TP1+)

The V15 backtest (21 signals with a complete evaluation run; 13 with price curves available) applied the same execution assumptions I care about in production: 3% slippage on entry and exit, stop loss at -40%, take profit at +80% (TP1), and conviction tier sizes of $10/$15/$25. It produced $+17.48 profit on $210 deployed, an 8.3% return on invested capital.

The interesting part is not the headline ROI. It’s the shape: the 0.85+ score band was meaningfully better than the 0.80–0.85 band. That suggests the system is not “slightly better than random”. It’s discriminating between setups that have genuine smart money consensus and setups that are just momentum noise.

what_didnt_work_yet

V15 still polls. That’s the biggest limitation. Polling enhanced transactions every 15 seconds works, but it’s not where the real edge is. The real edge is streaming alpha wallet token account changes via Helius Yellowstone gRPC and reacting in sub-second time.

Social scoring is intentionally minimal. In meme coins, social is often a lagging indicator, and sentiment is easier to manipulate than liquidity. The model reflects that by keeping social at 5% weight.

closing

The point of AxiomFlow isn’t to be clever. It’s to be correctly aligned with reality. Pump.fun is a graveyard. DexScreener is a lagging view of the graveyard. The only reliable early signal I’ve found is watching profitable wallets and measuring when they cluster.

The 0.63% graduation rate isn’t an obstacle. It’s a filter. If you can track the wallets that repeatedly navigate that filter, you stop guessing. You follow the money.
